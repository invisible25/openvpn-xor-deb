# Установка OpenVPN с XOR-обфускацией на ваш сервер (Debian, пошагово)

Эта инструкция написана для администратора VPS, который хочет поднять VPN, **устойчивый к блокировкам и DPI** (Deep Packet Inspection). Глубоких знаний Linux не требуется — достаточно уметь подключаться к серверу по SSH и копировать команды. Все команды можно копировать и вставлять как есть.

---

## Что это такое и зачем

`openvpn-xor` — это специальная сборка OpenVPN с **XOR-патчем Tunnelblick**. Она добавляет функцию `scramble` — лёгкую обфускацию (запутывание) трафика. Снаружи VPN-трафик перестаёт «выглядеть как OpenVPN», и провайдеру/файрволу труднее его распознать и заблокировать.

Технически наш пакет — это **тонкая надстройка** поверх обычного OpenVPN:

- он не заменяет весь сервер, а только подменяет один бинарный файл `/usr/sbin/openvpn` на XOR-версию (через штатный механизм `dpkg-divert`);
- оригинальный файл сохраняется рядом как `/usr/sbin/openvpn.distrib` — его всегда можно вернуть;
- все остальные части (systemd-сервисы, конфиги в `/etc/openvpn`, плагины) остаются от обычного пакета OpenVPN.

Именно поэтому пакет ставится **поверх уже работающего OpenVPN-сервера**, а не вместо него.

> **Важно сразу:** XOR/scramble должен поддерживаться с **обеих сторон** — и на сервере, и в клиентском приложении. Обычный официальный «OpenVPN Connect» обфускацию `scramble` **не умеет**. Подробности — в разделе [Клиентская часть](#клиентская-часть-обязательно-к-прочтению).

---

## Что понадобится

- VPS с **Debian 11, 12 или 13** (архитектура **amd64** — обычные облачные серверы Intel/AMD).
- Доступ к серверу по SSH под пользователем `root` (или через `sudo`).
- Один из 9 готовых `.deb`-пакетов из каталога `out/` (какой именно — см. Шаг 2 и Шаг 3).
- Несколько минут времени.

Общий порядок действий такой:

1. **Шаг 1.** Развернуть обычный OpenVPN-сервер скриптом Angristan.
2. **Шаг 2.** Узнать версию своего Debian.
3. **Шаг 3.** Скопировать и установить наш пакет `openvpn-xor`.
4. **Шаг 4.** Включить обфускацию `scramble` в конфигах сервера и клиентов.

---

## Шаг 1. Развернуть обычный OpenVPN-сервер (скрипт Angristan)

Если у вас ещё **нет** работающего OpenVPN-сервера, поднимите его проверенным скриптом [Angristan/openvpn-install](https://github.com/angristan/openvpn-install). Выполните под `root`:

```bash
curl -O https://raw.githubusercontent.com/angristan/openvpn-install/master/openvpn-install.sh
chmod +x openvpn-install.sh
./openvpn-install.sh
```

Скрипт **интерактивный** — он задаст несколько вопросов (порт, протокол UDP/TCP, DNS-серверы, имя первого клиента). Если не уверены — почти везде можно соглашаться со значениями по умолчанию.

После завершения скрипт создаст:

- конфиг сервера — `/etc/openvpn/server/server.conf`;
- системный сервис — `openvpn-server@server`;
- готовый клиентский файл — `~/<имя>.ovpn` (в домашней папке `root`, например `/root/client1.ovpn`).

На этом этапе у вас уже **обычный рабочий VPN** (пока без обфускации). Убедитесь, что он стартует и к нему можно подключиться, прежде чем идти дальше.

> Если OpenVPN-сервер у вас уже развёрнут (этим же или другим способом) — пропустите Шаг 1 и переходите к Шагу 2.

---

## Шаг 2. Узнать версию своего Debian

Пакет нужно брать **строго под свою версию Debian** — иначе будут ошибки несовместимости библиотек. Выполните на сервере:

```bash
. /etc/os-release; echo "$VERSION_ID"
```

Команда выведет число:

| Вывод | Версия Debian | Кодовое имя |
|------|---------------|-------------|
| `11` | Debian 11     | bullseye    |
| `12` | Debian 12     | bookworm    |
| `13` | Debian 13     | trixie      |

Запомните это число — оно понадобится в имени файла на следующем шаге (суффикс `-deb11` / `-deb12` / `-deb13`).

---

## Шаг 3. Установить пакет `openvpn-xor`

### 3.1. Выбрать нужный файл

В каталоге `out/` лежит **9 пакетов** — матрица из трёх версий OpenVPN, по три под каждый Debian. Имя файла строится так:

```
openvpn-xor_<версия-OpenVPN>-1-deb<номер-Debian>_amd64.deb
```

**Какую версию OpenVPN брать:**

- **2.6.20 — рекомендуется большинству.** Совпадает со штатной веткой 2.6.x, которую ставит скрипт Angristan; стабильная и проверенная.
- **2.5.9** — устаревшая. Берите только если нужна совместимость со старыми клиентами.
- **2.7.4** — новейшая. Для тех, кому нужны самые свежие возможности.

**Таблица: ваш Debian → какой файл брать (рекомендуемая версия OpenVPN 2.6.20):**

| Ваш Debian | Файл для установки |
|------------|--------------------|
| 11 (bullseye) | `openvpn-xor_2.6.20-1-deb11_amd64.deb` |
| 12 (bookworm) | `openvpn-xor_2.6.20-1-deb12_amd64.deb` |
| 13 (trixie)   | `openvpn-xor_2.6.20-1-deb13_amd64.deb` |

Если вам нужна версия 2.5.9 или 2.7.4 — выбирайте файл по тому же принципу, просто замените версию в начале имени. Например, для Debian 12 и OpenVPN 2.7.4 это будет `openvpn-xor_2.7.4-1-deb12_amd64.deb`.

### 3.2. Скопировать файл на сервер

> **Примечание.** Пакеты пока **не опубликованы онлайн** (нет apt-репозитория) — файл нужно скопировать на сервер вручную. См. раздел [Про ручное копирование пакетов](#про-ручное-копирование-пакетов).

С вашей локальной машины (Windows или Linux) скопируйте выбранный `.deb` на сервер командой `scp` (замените `IP_СЕРВЕРА` на адрес вашего VPS):

```bash
scp openvpn-xor_2.6.20-1-deb12_amd64.deb root@IP_СЕРВЕРА:/root/
```

### 3.3. (Необязательно) Сверить контрольную сумму

Чтобы убедиться, что файл скопировался без повреждений, можно сверить его SHA256-сумму с эталоном из `SHA256SUMS.txt`. На сервере:

```bash
sha256sum openvpn-xor_2.6.20-1-deb12_amd64.deb
```

Сравните вывод со строкой для этого файла в `out/SHA256SUMS.txt` — суммы должны совпасть.

### 3.4. Установить пакет

На сервере выполните (имя файла — под вашу систему):

```bash
dpkg -i openvpn-xor_2.6.20-1-deb12_amd64.deb
```

Если `dpkg` пожалуется на **неудовлетворённые зависимости** (например, ещё не стоит штатный `openvpn`), установите через `apt` — он сам подтянет всё нужное. Обратите внимание на `./` перед именем файла — это обязательно:

```bash
apt install ./openvpn-xor_2.6.20-1-deb12_amd64.deb
```

> **Важно:** берите файл строго под свою версию Debian. Пакет под «чужой» Debian приведёт к ошибкам несовместимости библиотек (libssl) и сервис не запустится.

После установки пакет напечатает подсказку и **не станет** сам перезапускать сервис — это сделано намеренно: обфускация `scramble` ещё не настроена, и преждевременный рестарт ничего бы не дал. Настроим её на следующем шаге.

---

## Шаг 4. Включить обфускацию (scramble)

Теперь включим саму XOR-обфускацию. Принцип простой: на сервере и на **каждом** клиенте должна стоять **одна и та же** строка `scramble` с **одним и тем же секретным ключом**.

### 4.1. Придумать секретный ключ

Ключ — это любая строка (лучше подлиннее, как надёжный пароль), например `mY-sup3r-Secret-Key-2026`. Он не передаётся по сети и служит «общим секретом» сервера и клиентов.

### 4.2. Добавить строку scramble на сервер

Откройте конфиг сервера `/etc/openvpn/server/server.conf` и добавьте строку:

```text
scramble obfuscate ВАШ_КЛЮЧ
```

(вместо `ВАШ_КЛЮЧ` подставьте свой ключ из п. 4.1).

> Есть альтернативный режим — `scramble xormask ВАШ_КЛЮЧ`. Для большинства случаев **рекомендуется `obfuscate`** — он надёжнее запутывает трафик.

### 4.3. Добавить ту же строку в каждый клиентский .ovpn

В **каждый** клиентский файл `.ovpn` (тот, что создал Angristan, например `/root/client1.ovpn`) добавьте **точно такую же** строку, что и на сервере:

```text
scramble obfuscate ВАШ_КЛЮЧ
```

Строка должна **полностью совпадать** с серверной (и режим, и ключ). Если они различаются — клиент не подключится.

### 4.4. Перезапустить сервер

```bash
systemctl restart openvpn-server@server
```

### 4.5. Раздать обновлённые .ovpn пользователям

Передайте пользователям обновлённые клиентские файлы `.ovpn` (со строкой `scramble`). Старые файлы без этой строки к обфусцированному серверу уже не подключатся.

> **Обратная совместимость.** Если строку `scramble` нигде не указывать, наш XOR-бинарь работает как **обычный OpenVPN** — ничего не ломается. Обфускация включается только наличием строки `scramble` с обеих сторон.

---

## Клиентская часть (обязательно к прочтению)

> **Внимание — это самая частая причина «не подключается».**
> Функция `scramble` работает только если **клиент тоже** использует OpenVPN с XOR-патчем. Обычный официальный клиент **«OpenVPN Connect» обфускацию `scramble` НЕ поддерживает** — с ним соединение просто не установится.

Что использовать на стороне клиента:

- **macOS** — [Tunnelblick](https://tunnelblick.net/). XOR-патч встроен «из коробки», ничего доставлять не нужно.
- **Windows / Linux / Android** — нужны **специальные сборки OpenVPN с XOR-патчем**. Стандартный «OpenVPN Connect» не подойдёт; ищите клиент именно с поддержкой `scramble` / XOR-патча Tunnelblick.

Правило простое: на клиенте должен стоять OpenVPN с XOR-патчем, и в его `.ovpn`-профиле — та же строка `scramble`, что на сервере.

---

## Проверка, что всё работает

На сервере выполните несколько команд:

```bash
openvpn --version
```
Покажет нашу сборку OpenVPN. В выводе **не должно быть** метки `[DCO]` — её отсутствие подтверждает, что используется именно XOR-бинарь (scramble работает в userspace, без DCO).

```bash
dpkg-divert --list openvpn
```
Покажет действующую подмену (diversion) — значит, наш бинарь встал на место штатного.

```bash
systemctl status openvpn-server@server
```
Сервис должен быть в состоянии **active (running)**.

И финальная, главная проверка: клиент с XOR-патчем и строкой `scramble` **успешно подключается** к серверу.

---

## Откат (вернуть штатный OpenVPN)

Если нужно вернуть обычный OpenVPN, просто удалите наш пакет:

```bash
apt remove openvpn-xor
```

(или эквивалент: `dpkg -r openvpn-xor`).

Это снимет подмену (`dpkg-divert`) и вернёт оригинальный `/usr/sbin/openvpn` из `.distrib`. После отката:

1. уберите строки `scramble` из `/etc/openvpn/server/server.conf` и из клиентских `.ovpn`;
2. перезапустите сервис:
   ```bash
   systemctl restart openvpn-server@server
   ```

## Troubleshooting (если что-то пошло не так)

**`dpkg -i` жалуется на зависимости.**
Установите пакет через apt — он сам подтянет недостающее:
```bash
apt -f install
```
или сразу ставьте через `apt install ./файл.deb` (с `./` перед именем).

**Сервис не стартует после установки.**
Почти всегда причина одна — взят пакет под **чужую версию Debian** (тогда в логах будут ошибки про `libssl` или про неразрешённые символы). Решение: поставить файл с правильным суффиксом `-debN` под свою систему (см. Шаг 2). Посмотреть логи:
```bash
journalctl -u openvpn-server@server -n 50
```

**Клиент не подключается после включения scramble.**
Проверьте две вещи:
1. строка `scramble` **идентична** на сервере и на клиенте (одинаковый режим и одинаковый ключ);
2. клиент использует **OpenVPN с XOR-патчем** (см. раздел [Клиентская часть](#клиентская-часть-обязательно-к-прочтению)), а не обычный «OpenVPN Connect».

## Про ручное копирование пакетов

Пока пакеты `openvpn-xor` **не опубликованы** в онлайн-репозитории (apt), поэтому установить их командой вида `apt install openvpn-xor` из интернета нельзя. Файл `.deb` нужно:

1. взять из каталога `out/` (рядом с этой инструкцией);
2. скопировать на сервер вручную (например, через `scp`, см. п. 3.2);
3. установить локально (`dpkg -i` или `apt install ./файл.deb`).

Когда появится онлайн-репозиторий, установку и обновления можно будет делать стандартными командами apt — но на текущий момент актуален именно ручной способ выше.
